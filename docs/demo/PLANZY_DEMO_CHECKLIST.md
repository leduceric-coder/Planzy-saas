# Planzy — Checklist avant démonstration

---

## J-1 (la veille)

- [ ] Vérifier que le déploiement Vercel est READY (page /rapports, /documents, /equipes)
- [ ] Vérifier que les données de démo sont présentes dans la base (voir DATASET_RECOMMANDE.md)
- [ ] Vérifier qu'il y a au moins 3 chantiers actifs avec des tâches
- [ ] Vérifier qu'il y a au moins 1 chantier "à risque" visible sur la page Chantiers
- [ ] Vérifier qu'il y a au moins 2 artisans avec des affectations cette semaine
- [ ] Vérifier que des photos sont disponibles (avec URLs signées fonctionnelles)
- [ ] Vérifier que des documents sont uploadés
- [ ] Vérifier qu'il y a au moins 1 alerte critique ou réserve ouverte visible sur Rapports

---

## Le jour J — 30 minutes avant

### Technique
- [ ] Ouvrir Planzy et se connecter avec le compte démo (ne pas être déconnecté pendant la démo)
- [ ] Naviguer une fois sur chaque écran pour confirmer qu'ils chargent correctement :
  - [ ] `/` (Dashboard)
  - [ ] `/chantiers`
  - [ ] `/chantiers/[id]` (la fiche du chantier "principal" de démo)
  - [ ] `/planning`
  - [ ] `/equipes`
  - [ ] `/documents`
  - [ ] `/rapports`
- [ ] Vérifier que les photos chargent (galerie visible, pas de placeholders cassés)
- [ ] Vérifier que le mini-Gantt de la fiche chantier est lisible
- [ ] Vérifier que les alertes Rapports sont cohérentes (pas de KPI à 0 si données présentes)
- [ ] Fermer tous les onglets inutiles du navigateur
- [ ] Désactiver les notifications système (Slack, email, téléphone)

### Affichage
- [ ] Passer en **mode clair** (light mode) — sauf si le prospect préfère le sombre
- [ ] Zoom navigateur recommandé : **100 %** (ou 90 % sur petits écrans)
- [ ] Résolution recommandée : **1440 × 900** ou plus
- [ ] Masquer la barre de favoris du navigateur pour plus de lisibilité
- [ ] Vérifier que la sidebar n'est pas en mode réduit (la déployer si nécessaire)

### Contenu
- [ ] Identifier le chantier "vedette" de la démo (celui avec le plus de données)
- [ ] Identifier l'artisan "vedette" (celui avec des tâches cette semaine)
- [ ] Identifier la photo "vedette" (avec badge Réserve ou À valider)
- [ ] Vérifier qu'au moins 1 rapport a été généré (pour l'historique visible)

---

## Pendant la démo

- [ ] Commencer par le Dashboard — ne jamais commencer par une page vide
- [ ] Rester en mode clair sauf demande explicite du prospect
- [ ] Suivre l'ordre : Dashboard → Chantiers → Fiche → Planning → Équipes → Documents → Rapports
- [ ] Ne pas modifier de données en direct (pas de création de tâche, d'issue, d'artisan)
- [ ] Ne pas aller dans les réglages ou la page Membres
- [ ] Ne pas montrer la page de connexion / inscription
- [ ] Si une page est vide : rester calme, dire "En conditions réelles, vous auriez ici vos données"
- [ ] Limiter chaque écran à sa durée cible (voir SCENARIO_5_MIN.md)
- [ ] Ne pas s'attarder sur le Gantt si les données sont insuffisantes

## Questions à poser avant de montrer la démo

Ces questions permettent d'adapter le discours :

1. "Combien de chantiers gérez-vous en même temps en moyenne ?"
2. "Vous utilisez quoi aujourd'hui pour le planning et le suivi ?"
3. "Quel est votre plus gros problème de coordination ?"
4. "Est-ce que vos équipes terrain sont à l'aise avec un smartphone ?"
5. "Vous cherchez plutôt un outil pour vous ou pour toute votre équipe ?"

---

## Signaux d'intérêt à surveiller

- Le prospect pose des questions sur son propre cas d'usage
- Il demande "est-ce qu'on peut faire [X] ?"
- Il compare avec son outil actuel
- Il demande le prix
- Il demande si ses artisans peuvent l'utiliser

**→ Si ces signaux apparaissent : ralentir, approfondir, ne pas chercher à tout montrer.**
